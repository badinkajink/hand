# Manta M8P V2.0 pin mapping used by this firmware

This project uses **TMC5160 drivers over a shared bit-banged SPI bus**.

STEP/DIR/EN pin assignments below are unchanged from BTT's official V2.0
pin mapping / Klipper config for this board (cross-checked via
`bigtreetech/Manta-M8P` GitHub docs and DeepWiki pin reference) -- only the
per-axis chip-select pin and the shared SPI bus are this project's own
addition. Verify against your own board silkscreen/schematic if anything
here seems off.

## Motor driver slots (M1-M8 -> joint index 0-7)

The board has 8 driver sockets; **this project only populates/uses J0-J5**
(6 axes, 2 per finger x 3 fingers -- see `host/examples/hand_control.py`'s
`STEPPER_JOINTS`). J6/J7 are wired in the STEP/DIR/EN and timer tables below
for completeness (the firmware's `STEPPER_NUM_AXES` is 8), but have no
TMC5160 populated (`tmc5160_cs[]` leaves them `NULL` -- `TMC5160_HasAxis()`
returns false, all SPI calls are no-ops for those two).

| Joint | Slot | STEP | DIR   | EN     | TMC5160 CS (was UART/PDN_UART) |
|-------|------|------|-------|--------|-------------------------|
| 0     | M1   | PE6  | PE5   | PC14 (active-low) | PC13 |
| 1     | M2   | PE2  | PE1   | PE4 (active-low)  | PE3  |
| 2     | M3   | PB8  | PB7 (inverted in BTT's Klipper cfg) | PE0 (active-low) | PB9 |
| 3     | M4   | PB4  | PB3   | PB6 (active-low)  | PB5  |
| 4     | M5   | PG13 | PG12  | PG15 (active-low) | PG14 |
| 5     | M6   | PG9  | PD7   | PG11 (active-low) | PG10 |
| 6     | M7   | PD4  | PD3   | PD6 (active-low)  | not populated |
| 7     | M8   | PC7  | PC8   | PD2 (active-low)  | not populated |

EN is active-low on every slot (the driver socket's ENN line -- enabled
when the pin is driven LOW). DIR polarity is **not** assumed correct from
BTT's table -- firmware exposes a per-axis `invert_dir` flag
(`Stepper_SetInvertDir` in `stepper.c`) because actual direction also
depends on how each motor's coil pairs are wired, which can't be known in
advance. It's compile-time only as of this writing (no protocol command
exposes it at runtime) -- add one in `protocol.c` if runtime toggling is
ever needed. Determine correct polarity empirically during bring-up.

## Shared SPI bus (bit-banged, all TMC5160s)

One physical bus, addressed per-axis only by chip-select (the CS column
above) -- not a separate SPI peripheral per axis:

| Signal | Pin |
|--------|-----|
| MOSI   | PG6 |
| MISO   | PG7 |
| SCK    | PG8 |

These 3 pins have no plain SPI-peripheral alternate function on this chip
(only OCTOSPI-manager functions are available there -- confirmed against
the datasheet, which is also why Klipper's own config bit-bangs this same
bus rather than using a hardware SPI peripheral). Each of the 6 populated
axes needs its socket's **SPI-mode jumpers** set (4 per socket, per BTT's
"TMC Drivers - SPI Mode" diagram in the board's user manual) before its
TMC5160 will respond on this bus at all -- see `docs/bringup.md`.

Bus timing is governed by `tmc5160_spi.c`'s `SPI_HALF_BIT_CYCLES_DIVISOR`.
This has real, non-obvious interaction with StallGuard-based homing: a
`spi_transact()` masks the step-timer and 1kHz supervisor-tick interrupts
for its full duration (BASEPRI), and `Stepper_HomingPollTick()` polls the
bus every 3ms during active homing -- a slow bus setting (this project
briefly ran at ~8ms per read) starves both step generation and the homing
timeout check badly enough to look exactly like a StallGuard/SGT tuning
problem when it wasn't one. Don't assume a wrong-looking stall-detection
result is necessarily a tuning issue; check this constant is still set for
a fast (~200us) transaction time first.

## MCU peripheral assignment (this firmware's choice, not BTT's)

Step pulses are generated by dedicated general-purpose timers running in
**update-interrupt-only** mode -- the STEP pin is toggled in software from
the ISR, not via hardware output-compare. This means the timer instance
does not need to be the one wired to that pin's alternate function; any GP
timer works as a pure interrupt tick source.

| Joint | Step-pulse timer |
|-------|-------------------|
| 0 (M1)| TIM2  |
| 1 (M2)| TIM3  |
| 2 (M3)| TIM4  |
| 3 (M4)| TIM5  |
| 4 (M5)| TIM7  |
| 5 (M6)| TIM16 |
| 6 (M7)| TIM17 |
| 7 (M8)| TIM15 |

Supervisory (1kHz velocity-profile recompute + homing timeout/StallGuard
poll) timer: TIM6.

(J4-J6 were originally TIM12/13/14, but those don't have standalone NVIC
vectors on this chip -- their interrupts are combined onto TIM8's
BRK/UP/TRG_COM lines. Caught by the first real build on the CB1; fixed by
moving to TIM7/16/17, which do have dedicated vectors.)
